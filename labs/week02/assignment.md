## Learning goals

By the end of this lab you should be able to:

- read a small BNF/EBNF grammar using the terms terminal, nonterminal, production, and start symbol;
- decide whether a short input is generated by a grammar;
- rewrite a simple recursive BNF production using EBNF repetition;
- distinguish a derivation / parse tree from an AST;
- explain precedence and associativity;
- connect grammar levels directly to recursive-descent parser functions;
- distinguish syntax errors from semantic errors such as an unbound name.

The lab deliberately uses a **very small language**. The objective is not to build a production compiler. The objective is to make the pipeline visible:

```text
source text
   ↓
tokens
   ↓
grammar / parser
   ↓
AST
   ↓
environment + evaluator
   ↓
result
```

## 1. Grammar reading — 15 min


Complete Exercises 1 and 2.

Use the instructor-owned reference grammar:

```text
labs/week02/examples/tiny-language.ebnf
```

Do not run Python for every grammar question. First reason from the grammar.

The central grammar is:

```ebnf
program     ::= { statement } expression EOF ;
statement   ::= "let" identifier "=" expression ";" ;

expression  ::= term { ("+" | "-") term } ;
term        ::= factor { ("*" | "/") factor } ;
factor      ::= number | identifier | "(" expression ")" ;

identifier  ::= letter { letter | digit | "_" } ;
number      ::= digit { digit } ;
```

Notice two intentional language-design choices:

- a program has zero or more `let` statements and then **one final expression**;
- an identifier begins with a letter; later characters may also contain digits or `_`.

The final expression has no semicolon and produces the program result.

## 3. Implement the expression parser — 30 min

Edit:

```text

```

The following parts are already implemented:

- tokenizer;
- token representation;
- AST data classes;
- parsing of the whole program and `let` statements;

You implement exactly three methods:

```python
parse_expression()
parse_term()
parse_factor()
```

Keep each method close to its grammar production.

### 3.1 `parse_expression`

Grammar:

```ebnf
expression ::= term { ("+" | "-") term } ;
```

Algorithm:

1. parse one `term`;
2. while `+` or `-` follows:
   - remember the operator;
   - parse the next `term`;
   - build a new `Binary` node from the tree so far and the new right side;
3. return the resulting tree.

### 3.2 `parse_term`

Grammar:

```ebnf
term ::= factor { ("*" | "/") factor } ;
```

Use the same pattern for `*` and `/`.

This separate grammar level is what gives multiplication/division higher precedence than addition/subtraction.

### 3.3 `parse_factor`

Grammar:

```ebnf
factor ::= number | identifier | "(" expression ")" ;
```

Handle three cases:

- `NUMBER` → `Number(...)`;
- `IDENT` → `Name(...)`;
- `(` → parse another expression and require `)`.

For anything else, raise `ParseError`. Do **not** silently skip unexpected input.
